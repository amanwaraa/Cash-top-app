CASH TOP — R74

1) مزامنة اقتصادية
- كل استعلام بيانات يستخدم path كمفتاح أساسي في Turso، بدون مسح الجدول.
- عند فتح الصفحة: الكاش أولاً، ثم فحص meta واحد فقط في الخلفية.
- عند تغير جهاز آخر: تُقرأ فقط مجموعات البيانات الخاصة بالصفحة التي تغير ختمها.
- العمليات المحلية المعلقة تُرفع فور دخول الصفحة.
- المزامنة اليدوية أصبحت خاصة بالصفحة الحالية، ولا تسحب كل بيانات الشركة.
- رفع عدة تعديلات يستخدم فحص meta واحد للدفعة، ثم يكتب المجموعات المعدلة فقط.
- القيم الافتراضية على جهاز/لابتوب جديد تبقى seeded محلياً ولا تُرفع قبل تنزيل النسخة السحابية، لمنع الكتابة الزائدة ومنع استبدال بيانات موجودة.
- سجل التدقيق السحابي معطل افتراضياً لتوفير الكتابة والتخزين.

2) تحديثات بين الأجهزة
- فحص خفيف للـ meta أثناء بقاء الصفحة ظاهرة.
- meta يحتوي أختام تغيير منفصلة لكل dataset.
- لا يتم تنزيل كل الصفوف عند كل فحص؛ عند وجود تغيير يُطلب dataset المتغير المرتبط بالصفحة فقط.
- دمج أختام التغيير يتم داخل SQLite بواسطة json_patch لتجنب ضياع تحديث جهاز عند الكتابة المتزامنة.

3) الكاش
- جميع صفحات التطبيق الـ HTML محفوظة مسبقاً في Service Worker.
- الصفحة المخزنة تُعرض فوراً حتى مع وجود الإنترنت.
- تحديث ملفات HTML/JS/CSS يتم بالخلفية وبفترات متباعدة ولا يؤخر التنقل.
- Turso وطلبات البيانات الحية لا تدخل Cache Storage.

4) الإشعارات
- صفحة وقسم الإشعارات وإشعارات المدير الذكية موجودة.
- تم تعطيل إشعار المدير الخاص بإنشاء فاتورة جديدة فقط.
- لا يوجد Firebase Push أو Vercel/MongoDB.
- ملخص آخر اليوم يستخدم Service Worker محلياً عند دعم المتصفح، ولا يستهلك Turso.

5) تسجيل الدخول
- مفتاح الشركة فقط هو الذي يبقى محفوظاً محلياً.
- جلسة الحساب داخل التبويب، مع fallback عبر window.name للمتصفحات المكتبية التي تمنع sessionStorage.
- جهاز جديد لا يرفع defaults قبل bootstrap السحابي.

6) الخطط
- Plus وPro كما هي.
- خطة مخصصة: فواتير/عملاء/مصاريف/موردون يومياً، وموظفون/مخازن/فروع/منتجات كحدود ثابتة.
- صفحة الإعدادات تعرض مفتاح الشركة وتفاصيل الخطة فقط في بطاقة الاشتراك.

7) الاستيراد
- يمكن استيراد نسخة تخص مفتاحاً آخر.
- يحتفظ البرنامج بهوية المفتاح والخطة والمدير الحاليين.
- يرفع فقط الأقسام التي تغيرت، بدون قراءة تحقق قبل/بعد كل قسم.
